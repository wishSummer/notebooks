# 个人 AI 操作系统建设计划

> 定位：以 Codex 作为个人工作助理，持续读取项目资料、推进任务、执行可授权的工具操作，并把成果沉淀到 Obsidian 与 GitHub。第一阶段不自建 LLM、LangGraph 或 LlamaIndex；只有原生能力不足时才增加外部服务。

> 更新日期：2026-07-10

## 1. 总目标

建立一套可长期运行的个人工作系统，让 Codex 从“临时回答问题的工具”转变为“有固定工作规范、可定期执行、能持续推进目标的个人助理”。

系统重点解决三个问题：

1. **自动化知识产出**：定期整理笔记、研究资料与项目实践，形成专题笔记、文章草稿和决策记录。
2. **持续推进任务**：把长期目标拆成项目、里程碑和下一步行动，定期检查阻塞、更新状态并执行权限范围内的工作。
3. **完成指定目标**：围绕明确验收标准持续工作，产出文档、代码、报告、图片或工作流；遇到高风险决策时请求人工确认。

6 个月目标：

- 形成稳定的 Codex 个人助理运行规则。
- 建立可检索、可维护的 Obsidian 个人知识库。
- 建立用 GitHub 管理的项目与成果资产库。
- 运行每日、每周和每月自动化任务。
- 推进[[AI内容生产系统]] 至可演示 MVP。
- 每月至少形成 1 个可展示成果。

## 2. 核心原则

1. **Codex 优先**：先使用 Codex 原生任务、文件、Skills、插件、浏览器、Computer Use 和 Scheduled Tasks。
2. **文件即记忆**：关键背景、目标、偏好、决策和项目状态必须写入文件，不依赖聊天记忆。
3. **结果必须落盘**：重要结论不能只存在于会话中，必须进入 Obsidian 或 GitHub。
4. **自动执行，分级审批**：低风险任务可自动完成；发布、付款、删除、账号操作和重大方向调整必须人工确认。
5. **目标驱动**：每项工作都要有目标、输入、输出、截止条件和验收标准和文档，便于人工浏览及调整每一部分的内容。
6. **逐步增强**：没有明确瓶颈时，不引入 LangGraph、LlamaIndex、向量数据库或独立 Agent 平台。

## 4. Codex 个人助理职责

### 4.1 知识助理

- 读取 Obsidian 的新增笔记和项目资料。
- 去重、归类、补充双链、提炼结论和待验证假设。
- 将零散资料整理成原子笔记、专题综述和文章草稿。
- 标注事实、推断、个人判断、来源和更新时间。
- 识别知识缺口，生成下一轮研究问题。

### 4.2 项目助理

- 读取长期目标和项目状态。
- 将目标拆为里程碑、任务、下一步行动与验收标准。
- 发现阻塞、依赖和长期未推进事项。
- 自动完成权限范围内的文档、代码、测试、整理和分析任务。
- 更新项目看板、状态记录和周报。

### 4.3 生产助理

- 为 AI装修项目生成需求分析、方案草稿、报价项和验证材料。
- 为 AI内容项目生成选题、研究、脚本、分镜和生产任务单。
- 调用已授权的 ComfyUI、FFmpeg、浏览器或脚本执行生产步骤。
- 对产出做结构、完整性、事实依据和基础质量检查。

### 4.4 复盘助理

- 每周汇总完成事项、未完成原因、关键学习和下周优先级。
- 每月检查目标漂移、低价值任务和资源分配。
- 将重复经验转化为 `AGENTS.md` 规则、Skill、模板或脚本。

## 5. 记忆与上下文管理

Codex 不应依赖 ChatGPT 会话记忆作为系统唯一依据。个人记忆采用四层结构：

| 层级    | 内容                | 载体                             |
| ----- | ----------------- | ------------------------------ |
| 全局偏好  | 沟通方式、决策原则、长期关注方向  | 全局 `AGENTS.md` + Obsidian 个人档案 |
| 项目规则  | 项目目标、目录、命令、验收标准   | 项目根目录 `AGENTS.md`              |
| 可复用流程 | 研究、整理、复盘、发布前检查    | Codex Skills                   |
| 任务上下文 | 当前目标、临时约束、正在处理的输入 | Codex 当前任务与项目文档                |

- 最后更新时间

### 知识写入规则

1. 原始输入先进入 `01_收集箱`，由定时任务整理。
2. 一篇长期笔记尽量只表达一个主题。
3. 重要结论必须包含依据、日期和适用范围。
4. 自动生成内容先标记 `status: draft`，人工确认后改为 `status: verified`。
5. 每篇项目笔记必须有 `next_action` 和 `updated_at`。
6. 重复内容优先合并或链接，不机械增加笔记数量。

## 8. Codex 自动化任务设计

自动化任务分为“独立定时任务”和“延续当前上下文的任务”。独立任务适合日报和固定检查；持续推进同一目标时，应让定时执行返回同一个 Codex 任务，以保留上下文。

### 每日自动化

**任务：知识收集箱整理**

- 读取过去 24 小时新增或修改的笔记。
- 去重、分类并建议双链。
- 将可复用结论整理为草稿。
- 生成 `05_复盘/日报/YYYY-MM-DD.md`。
- 不删除原始笔记，不将未经核实内容标为事实。

**任务：今日任务推进**

- 读取 `当前季度目标.md`、`当前项目总览.md` 和项目状态。
- 找出一个最高价值且可独立完成的下一步。
- 在权限范围内执行，并更新结果与阻塞。
- 涉及发布、费用、删除、对外沟通或方向变更时停止并请求审批。

### 每周自动化

**任务：周复盘与下周计划**

- 汇总本周笔记、Git 提交、Issue 和项目状态。
- 输出成果、偏差、阻塞、关键学习和下周三个优先事项。
- 更新 `当前项目总览.md`。
- 将反复出现的问题建议沉淀为规则、Skill 或模板。

**任务：知识产出**

- 从本周高价值主题中选择一个。
- 结合已有笔记和必要的最新资料完成研究。
- 产出一篇结构化文章或专题报告草稿。
- 列出来源、待核实内容和适用对象。

### 每月自动化

**任务：目标审计**

- 检查季度目标和项目是否发生目标漂移。
- 识别低价值、长期阻塞或重复任务。
- 提出继续、暂停、归档建议，等待人工确认。
- 生成下月里程碑和一个可展示成果目标。

### 自动化运行前提

- 需要本地文件时，电脑保持开机且 Codex/ChatGPT 桌面应用运行。
- 自动化使用默认沙箱和权限策略，文件目录必须在允许范围内。
- 先手动运行并验证任务提示，再设为定时任务。
- 前三次定时结果必须人工复核，再逐步扩大自动执行范围。

## 9. Skills 建设计划

优先创建四个小而稳定的 Skill：

| Skill | 输入 | 产出 |
|---|---|---|
| `knowledge-curator` | 新增 Obsidian 笔记 | 分类、去重、双链、摘要、待验证项 |
| `project-driver` | 项目目标和状态 | 下一步任务、执行结果、阻塞、状态更新 |
| `weekly-review` | 本周笔记和项目记录 | 周复盘、优先级、规则改进建议 |
| `content-pipeline` | 主题、受众、资料 | 研究提纲、初稿、审核清单、发布资产 |

只有流程重复出现三次以上、步骤相对稳定时，才将其固化为 Skill。涉及外部服务时，优先安装或连接成熟插件；仍不能满足需求时再开发 MCP 或脚本。

## 10. 技术栈与引入顺序

### 第一优先级：直接使用

| 能力 | 方案 |
|---|---|
| 核心助理 | Codex 桌面应用 |
| 长期知识 | Obsidian Markdown |
| 项目与代码 | Git + GitHub |
| 持久规则 | `AGENTS.md` |
| 可复用流程 | Codex Skills |
| 定时执行 | Scheduled Tasks |
| 本地执行 | Shell、浏览器、Computer Use |
| 外部服务 | Plugins / MCP |
| 图片与视频 | ComfyUI API + FFmpeg |

### 第二优先级：出现瓶颈后引入

| 工具 | 引入条件 |
|---|---|
| Python 脚本 | Codex 需要稳定执行批处理、格式转换或 API 调用 |
| GitHub Actions | 需要仓库级自动测试、构建或发布 |
| SQLite/PostgreSQL | Markdown 已不适合管理结构化任务或业务数据 |
| LlamaIndex / 向量数据库 | 笔记规模增大，文件搜索与目录路由无法稳定找到相关知识 |
| LangGraph | 流程需要复杂状态机、可恢复执行、并行分支和确定性重试 |
| 独立 LLM/API 服务 | 需要面向外部用户提供产品服务，而非只服务个人工作流 |

结论：LangGraph 和 LlamaIndex 是可选扩展，不是个人助理第一阶段的前置条件。

## 11. 分阶段实施路线

### 第一阶段：1 周，建立可工作的助理基础

目标：让 Codex 每次都能读取统一规则、目标和项目状态。

任务：

1. 调整 Obsidian 目录并建立个人档案、季度目标、项目总览。
2. 在个人工作仓库创建精简的 `AGENTS.md`。
3. 建立项目模板、原子笔记模板和周复盘模板。
4. 手动运行一次“知识收集箱整理”和“项目推进”流程。
5. 为 AI装修、AI内容生产分别明确一个 30 天里程碑。
6. 定义自动执行与必须审批的边界。

交付物：

- Codex 个人助理规则 v1
- Obsidian 基础目录与模板
- 当前季度目标和项目总览
- 两个项目的 30 天里程碑

### 第二阶段：1 个月，运行稳定的自动化闭环

目标：Codex 能定期整理知识、生成周报并推动项目下一步。

任务：

1. 创建并测试每日知识整理定时任务。
2. 创建并测试每周复盘与项目推进定时任务。
3. 建立 `knowledge-curator`、`project-driver` 两个 Skill。
4. 连接 GitHub，读取提交和 Issue；写操作遵循审批策略。
5. 每周产出一篇专题草稿，每月完成一个可展示成果。
6. 记录失败任务、误判和重复反馈，迭代 `AGENTS.md`。

验收指标：

- 自动化成功运行率达到 80% 以上。
- 每周至少 1 篇结构化知识产出。
- 每周至少推进 1 个项目里程碑任务。
- 项目状态与真实进度基本一致。

### 第三阶段：3 个月，形成项目生产能力

目标：Codex 不只整理和规划，还能完成两类项目的具体生产任务。

任务：

1. 建立内容研究、写作、审核与归档 Skill。
2. 接入 ComfyUI API 和 FFmpeg 的最小可用工作流。
3. AI装修项目完成方案生成与报价草稿流程。
4. AI内容项目完成选题、脚本、分镜和素材任务单流程。
5. 将可重复的命令和转换工作固化为脚本。
6. 评估文件检索是否已出现明显瓶颈，再决定是否引入 LlamaIndex。

验收指标：

- 至少 2 个稳定可重复的端到端工作流。
- AI装修形成 1 套可展示案例。
- AI内容生产形成 3 个完整样稿或 1 个视频样片。
- 人工只处理关键判断和最终审核。

### 第四阶段：6 个月，形成个人 AI 工作系统 1.0

目标：让 Codex 持续服务知识积累、项目交付和商业验证。

任务：

1. 完善日、周、月自动化与异常处理规则。
2. 建立成果指标面板：知识产出、项目进度、可展示成果、有效反馈。
3. AI装修完成可演示 MVP 和真实用户验证。
4. AI内容生产完成稳定生产流程和发布复盘。
5. 根据真实复杂度决定是否增加 LangGraph、LlamaIndex、数据库或独立服务。
6. 将成熟 Skills、模板和脚本纳入 GitHub 版本管理。

验收指标：

- 每月至少 1 个可展示成果。
- 两个核心项目至少一个获得真实用户反馈。
- 自动化任务有明确成功、失败和需审批状态。
- 知识库能够支持项目决策，而不是只增加笔记数量。

## 12. AI装修项目应用规划

### Codex 的角色

- 读取装修行业笔记、用户访谈和历史方案。
- 生成需求问卷、户型分析清单和设计方案草稿。
- 根据规则库生成材料、工序和报价项草稿。
- 调用 ComfyUI 工作流生成风格参考图或效果图候选。
- 整理客户反馈，更新方案和项目记录。
- 生成案例报告、演示材料和下一轮验证计划。

### 3 个月最小闭环

```text
客户资料 / 户型图 / 毛坯图
            |
            v
Codex 整理需求和缺失信息
            |
            v
设计方案草稿 + 报价项草稿
            |
            v
ComfyUI 效果图候选
            |
            v
人工设计审核与修正
            |
            v
方案册 + 客户反馈 + 项目复盘
```

必须人工确认：结构改造建议、施工安全判断、正式报价、合同承诺和对客户发送的最终方案。

## 13. AI内容生产项目应用规划

### Codex 的角色

- 根据知识库和目标受众生成选题池。
- 搜集资料并区分事实、观点和推断。
- 生成文章、短视频脚本、分镜和视觉提示词。
- 调用图片或视频工具生产候选素材。
- 执行一致性、事实、结构、字幕和格式检查。
- 汇总发布数据，提出下一轮实验。

### 3 个月最小闭环

```text
选题目标 / 受众 / 原始资料
            |
            v
Codex 研究与生成内容草稿
            |
            v
脚本 / 分镜 / 视觉提示词
            |
            v
ComfyUI / 视频工具生成素材
            |
            v
AI 初检 + 人工终审
            |
            v
发布资产 + 数据复盘 + 知识沉淀
```

必须人工确认：事实敏感内容、版权风险、账号发布、商业承诺和最终品牌表达。

## 14. 权限与安全边界

### 可自动执行

- 读取授权目录内的资料。
- 整理、重命名建议、生成草稿和内部报告。
- 在工作区创建或修改文档和代码。
- 运行非破坏性检查、测试和数据分析。
- 更新内部项目状态与复盘草稿。

### 必须人工审批

- 删除、覆盖或大规模移动原始资料。
- 对外发送邮件、消息、文章或客户方案。
- 付款、购买服务、修改账号权限或处理密钥。
- 合并主分支、正式发布或部署生产系统。
- 改变长期目标、暂停核心项目或做重大资源投入。
- 涉及法律、财务、施工安全和隐私的最终结论。

## 15. 长期维护规则

### 每日

- 原始想法只需快速记录，由 Codex 定时整理。
- Codex 更新日报、完成事项、阻塞和下一步。
- 不为了“笔记数量”制造低价值内容。

### 每周

- 人工审阅 Codex 周报并确认下周三个优先事项。
- 检查自动化失败、误判和越权风险。
- 将重复流程沉淀为模板或 Skill。
- 至少推进一个能被验收的项目成果。

### 每月

- 审核目标是否漂移，决定继续、暂停或归档项目。
- 检查知识库是否存在重复、陈旧和无依据内容。
- 评估 Codex 自动化节省的时间和产生的有效成果。
- 输出一个可展示成果，并收集真实反馈。

### 每季度

- 更新长期目标、个人档案和项目优先级。
- 审计 `AGENTS.md`、Skills、插件权限和定时任务。
- 只根据真实瓶颈决定是否增加新技术组件。

## 17. 最终判断标准

这套系统是否成功，不看安装了多少框架，而看以下结果：

- Codex 是否能快速理解你的背景和当前目标。
- 每周是否产生可复用知识和可验收成果。
- 项目是否持续前进，而不是只生成计划。
- 重要结果是否进入 Obsidian 和 GitHub。
- 自动化是否可靠、可审查、不会越过人工边界。

最终形态不是“自建一个万能 Agent 平台”，而是：

> 你负责目标、判断和关键审批；Codex 负责理解上下文、执行工作、推进任务和沉淀成果；Obsidian 与 GitHub 负责保存可持续积累的个人资产。
