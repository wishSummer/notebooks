# Codex 自动推进任务

> 本文件是 Codex 定时任务的唯一控制入口。每次运行先读取本文件，再读取被选中项目的资料；完成一个可验证步骤后，将结果写回本文件和对应项目文档。

## 1. 总目标

让 Codex 作为个人工作助理，持续完成以下工作：

1. 自动整理和产出可复用知识。
2. 主动推进当前最高优先级项目。
3. 将长期目标拆成可执行、可验证的下一步。
4. 把成果沉淀到 Obsidian；代码与可交付资产进入 GitHub。
5. 遇到权限、风险或关键决策时停止执行并请求人工确认。

## 2. 每次运行协议

Codex 每次定时运行必须依次执行：

1. 读取本文件，确认 `automation_enabled: true`。
2. 检查“等待人工处理”是否存在未解决事项。
3. 从“当前目标队列”中选择优先级最高、状态为 `active` 且未阻塞的目标。
4. 读取该目标关联的项目文档、最近复盘和必要知识笔记。
5. 选择一个本次能够独立完成并验证的最小步骤。
6. 执行任务，优先形成实际成果，不只生成新的计划。
7. 对结果进行验证；无法验证时说明原因和所需条件。
8. 更新项目文档的当前状态、下一步、阻塞和更新时间。
9. 更新本文件的运行状态与运行日志。
10. 若所有目标均阻塞或没有有效工作，记录原因，不制造低价值内容。

## 3. 任务选择规则

按以下顺序选择工作：

1. 修复阻碍当前里程碑的明确问题。
2. 完成已经定义验收标准的项目任务。
3. 完善可直接支持项目推进的知识或工具。
4. 整理过去 24 小时新增但尚未归类的资料。
5. 生成周报、月报或阶段复盘。

不得因为任务容易而跳过更高优先级目标。不得只创建任务清单而不推进任务本身。

## 5. 自动执行边界

### 可以自动执行

- 读取授权目录中的笔记、代码和项目资料。
- 创建或修改内部 Markdown 文档。
- 整理知识、生成草稿、更新项目状态和复盘。
- 运行只读检查、测试、格式验证和链接验证。
- 在项目工作区创建代码或脚本，并执行非破坏性验证。
- 发现重复流程时提出 Skill、模板或自动化建议。

### 必须等待人工确认

- 删除非空原始文档或批量覆盖用户内容。
- 对外发布文章、视频、邮件、消息或客户方案。
- 执行付款、购买、账号权限、密钥或隐私相关操作。
- 合并主分支、正式部署或修改生产环境。
- 改变长期目标、暂停核心项目或做重大资源投入。
- 给出法律、财务、医疗、施工安全方面的最终结论。

## 6. 停止与阻塞规则

出现以下情况时停止当前步骤，并写入“等待人工处理”：

- 缺少完成任务必须的业务选择或原始资料。
- 操作超出当前文件、网络或应用权限。
- 需要删除、发布、付费、登录或修改外部系统。
- 不同项目资料相互矛盾，无法可靠判断。
- 连续三次运行遇到同一阻塞条件。
- 任务结果无法定义或验证。

阻塞记录必须说明：阻塞目标、已尝试内容、需要用户提供什么、解除阻塞后的下一步。

## 10. 定时任务提示

将以下内容作为 Codex Scheduled Task 的任务提示：

```text
你是我的个人工作助理。请在 Obsidian vault `D:\self-project\notebooks` 中执行一次自动推进循环。

第一步必须读取：
`00_个人系统/Codex_自动推进任务.md`

严格遵循该文件中的运行协议、任务优先级、验收标准、权限边界、停止规则和日志格式。

本次只选择一个最高优先级且未阻塞的目标，完成一个可独立验证的最小步骤。优先产出实际成果，不要只生成计划。

完成后必须：
1. 验证产出；
2. 更新对应项目文档；
3. 更新控制文件中的“本次运行状态”和“运行日志”；
4. 明确报告完成内容、验证结果、下一步或阻塞；
5. 不执行需要人工确认的操作。

如果没有可执行任务，记录具体原因，不创建无价值内容。如果 automation_enabled 不是 true，立即停止并报告自动化已关闭。
```

## 11. 推荐调度方式

- **项目目录**：`D:\self-project\notebooks`
- **运行位置**：Local，直接更新当前 vault
- **建议频率**：工作日每天一次
- **建议时间**：20:30（Asia/Shanghai）
- **上下文方式**：优先从同一个 Codex 任务定期继续，保留推进上下文
- **权限模式**：仅允许写入 vault 和必要工作区；网络或外部应用按需单独授权

首次创建定时任务前，先在普通 Codex 任务中手动执行一次上面的提示，并审查前三次结果。

## 12. 人工维护规则

每周至少检查一次：

1. 当前目标优先级是否仍然正确。
2. 下一步是否足够具体并可验收。
3. 是否存在长期阻塞或重复失败。
4. Codex 是否产生了低价值文档或重复内容。
5. 是否需要把稳定流程沉淀为 Skill 或脚本。

需要暂停自动推进时，将 YAML 中的 `automation_enabled` 改为 `false`。
